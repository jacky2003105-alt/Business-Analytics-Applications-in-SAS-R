12.1文字探勘是什麼

從文字到表格

文字是非結構化資料：沒有固定欄位，長短不一。文字探勘要做的事，就是把文字「結構化」——變成有一定格式的表格。最簡單的做法是：算每個詞出現幾次，再套用分群或分類的演算法。老師講義用三種表格說明：

例 1：一篇文章，每個字出現幾次（詞頻表）

字 我 你 他 好 早
頻率 5 3 0 2 1

例 2：很多篇文章，有沒有出現這個字（0／1 矩陣）

文章 我 你 他 好 早
1 1 0 1 1 1
2 0 0 1 1 1
3 1 0 1 0 0

例 3：很多篇文章，每個字出現幾次——這就是文件–詞矩陣（document-term matrix，DTM）：

文章 我 你 他 好 早
1 5 0 3 4 1
2 0 0 2 1 1
3 3 0 6 0 0

一旦變成例 3 的矩陣，每篇文章就是一列、每個詞就是一個變數——和第 9 章的顧客資料、第 11 章的財務比率沒有兩樣，可以計算距離、分群、做 PCA。

  • 關聯分析：詞彙之間的關係（相關係數、相似指數），例如「價格」常和「貴」一起出現。
  • 分類（classification）：依使用者給的類別自動分類文件，例如把客訴分到「物流／品質／服務」，可用 naive Bayes、SVM、隨機森林（第 10 章）。
  • 集群分析（clustering）：依文件本身的相似性分群，不需要事先給類別（第 9 章）。

斷詞

斷詞（word segmentation）是把句子切成一個一個「有意義的詞」：

我最喜歡上統計系的課 → 我／最／喜歡／上／統計系／的／課

英文有空格天然分開，中文沒有，切錯就會影響後面所有分析（「統計系」被切成「統計／系」，詞頻就不對了）。斷詞也是問答系統、摘要、文件檢索、翻譯、語音辨識、主題模型、情緒分析的第一步。

  2. (B)Rows are words, columns are letters

Q2

簡答｜中為什麼要斷詞

Why is word segmentation a necessary first step for Chinese text mining but not for English text mining?

中文題意

為什麼中文文字探勘需要先斷詞，英文卻不用？

答案

English words are separated by spaces, so text can be split into words (tokens) directly. Chinese text has no spaces between words, and the same characters can be grouped in different ways, so an algorithm or dictionary is needed to cut a sentence into meaningful words first. If segmentation is wrong (for example a department name is split into two pieces), the word counts, word clouds and all later analyses will be wrong.

解析

英文以空格分詞，中文沒有，必須靠斷詞工具（jieba）與詞典；斷詞錯誤會一路影響詞頻、文字雲與分群結果。

You analyze 50 song lyrics that together contain 3,000 distinct words. In a document-term matrix with one row per song, what are the dimensions and what is typical?

  1. (A)3000 × 50, and almost every cell is a large positive number
  2. (B)50 × 50, and the diagonal shows how many words each of the songs has

12.2環境設定：用 reticulate 呼叫 Python 的 jieba

R 早期的中文斷詞套件（Rwordseg、jiebaR）常常裝不起來，老師今年改用 Python 最流行的斷詞工具 jieba，再透過 reticulate 套件讓 R 直接呼叫 Python。第一次使用要建立一個獨立的 Python 環境並安裝 jieba（老師另外提供了安裝說明 PDF）：

R
library(reticulate)

virtualenv_create("r-jieba")                 # 建立一個叫 r-jieba 的 Python 虛擬環境（只要做一次）
use_virtualenv("r-jieba", required = TRUE)   # 使用這個環境
py_install("jieba", pip = TRUE)              # 在環境裡安裝 jieba（只要做一次）

之後每次使用只要兩步：指定環境、載入 jieba。

R
library(reticulate)
use_virtualenv("r-jieba", required = TRUE)
jieba <- import("jieba")         # 把 Python 的 jieba 模組載入成 R 物件
  • import("jieba") 回傳一個 R 物件，Python 模組裡的函數用 $ 取用：jieba$cut()、jieba$add_word()。
  • jieba$cut() 回傳的是 Python 的「迭代器」，要用 iterate() 一個一個取出、unlist() 攤平成字元向量。老師把這兩步包成一個自訂函數（第 3 章）：
R
cut_words <- function(text) {
  unlist(iterate(jieba$cut(text)))
}

"^\\s*$" 從頭（^）到尾（$）都是空白字元（\\s*，零個以上）——也就是空字串或只有空白
"^[[:punct:]]+$" 從頭到尾都是標點符號（[[:punct:]] 代表任一標點，+ 一個以上）

!str_detect() 是「不符合」的才留下。

TF-IDF：找出「這個作者特有」的詞

高頻詞常常是大家都用的詞（「你」「我」）。TF-IDF 用來找「在這份文件常出現、但在其他文件少出現」的代表詞：

\[\text{tf-idf}(t,d)=\underbrace{\frac{\text{詞 } t \text{ 在文件 } d \text{ 的次數}}{\text{文件 } d \text{ 的總詞數}}}_{\text{TF：詞頻}}\times\underbrace{\ln\frac{\text{文件總數}}{\text{含有詞 } t \text{ 的文件數}}}_{\text{IDF：逆文件頻率}}\]

每份文件都出現的詞，IDF = ln(1) = 0，TF-IDF 就是 0。

Describe the steps to cluster a set of documents (for example, song lyrics) using k-means in R.

(1) Segment each document into words (jieba for Chinese, unnest_tokens for English) while keeping the document id. (2) Clean the tokens: remove blanks, punctuation, stop words, and possibly very rare words. 解析

就是 12.6 節「從文字到分群與 PCA」的流程：斷詞→清理→DTM→標準化→kmeans→解讀。

補充idea 關鍵字萃取的另一種想法

詞頻與 TF-IDF 是用「次數」找關鍵字。像 cortical.io 的線上關鍵字萃取工具則用「語意」：把詞表示成語意向量（semantic fingerprint），找出最能代表整篇文章意思的詞，即使那個詞只出現一次。現代的做法（詞向量、BERT、大型語言模型）也是這個方向——但不論方法多新，「把文字轉成數字，再套用統計方法」的核心想法都和本章一樣。
